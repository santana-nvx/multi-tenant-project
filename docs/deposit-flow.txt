============================

PART 2 — PLAYER PAYS, GATEWAY CONFIRMS (separate request, later)
-------------------------------------------------------------------

 [Player pays on gateway's own page]
           |
           v
 [Gateway's server]
        |  POST callback_url  { order_id, order_status, token, ... }
        v
 +--------------------+
 | DepositCallback       |  (public route - no auth:api, gateway isn't a player)
 | Controller             |
 +---------+----------+
           v
 +-----------------------------------------------------------+
 |  DepositCallbackService::handle()                          |
 |                                                              |
 |   1. GatewayCallbackChecker -> verify MD5 signature          |
 |      fake?  ->  422, stop here                               |
 |   2. find Transaction by order_id                           |
 |   3. already processed_at?  ->  no-op (idempotency)          |
 |   4. order_status === completed ?                            |
 |        YES -> lockForUpdate() Wallet, bcadd() balance,       |
 |               Transaction -> success                          |
 |        NO  -> Transaction -> failed                           |
 +---------+---------------------------------------------------+
           v
 +--------------------+
 |  {"status": true}     |  <- tells the gateway "handled, stop retrying"
 +--------------------+

        v

 +---------+----------+
           v
   { balance: "500.00", currency: "MYR" }   <- reflects Part 2's crediting


THE ONE RULE THIS WHOLE DIAGRAM FOLLOWS
------------------------------------------
Every box only ever talks to the box directly next to it - the controller
never touches the gateway directly, the driver never touches the database
directly. Part 1 and Part 2 are TWO COMPLETELY SEPARATE HTTP REQUESTS,
arriving at different times, from different callers (the player's browser
vs. the gateway's own server) - that separation is exactly why the money is
only ever trusted as real in Part 2, never Part 1.
